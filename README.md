# Радар ИИ-видимости · Яндекс Алиса (Keys.so)

Онлайн-сервис для отдела продаж / SEO-агентства: снимает **видимость сайтов в ИИ-выдаче
Яндекс Алисы** по данным Keys.so, сравнивает клиента с конкурентами по десяткам критериев,
сохраняет всё в память и на цифрах доказывает клиенту, что **необходимо продвигаться по
семантике** — с графиками, семантическим разрывом, прогнозом трафика и готовым планом работ.

## Что умеет

1. **Внести несколько адресов сайтов** и одним кликом разобрать их в список доменов.
2. **Назначить роли** — 1 сайт клиента (с которым сравниваем) + значимые конкуренты.
3. **Снять ИИ-видимость** по каждому домену через Keys.so:
   - цитирования в ответах Алисы (`domain_dashboard/ai-answers`),
   - ИИ-конкуренты и их видимость (`organic/ai-concurents`),
   - органическая сила ТОП-1/3/5/10/50 (`domain_dashboard`),
   - частотность Wordstat (`organic/keywords`).
4. **Сохранить всю видимость в память** (локальная база SQLite `data/analytics.db`) и
   сравнивать проекты по разным критериям.
5. **Показать клиенту**:
   - **а) сильные стороны клиента** — запросы, где в ИИ-ответах процитирован только он;
   - **б) сильные стороны конкурентов** — где они впереди в ИИ-выдаче;
   - **в) почему НЕОБХОДИМО продвигаться** — графики (столбчатые + радар), таблица
     упущенной семантики и прогноз трафика по этой семантике;
   - **г) план работ** на основании полученных цифр (генерирует OpenAI).
6. **Светлая / тёмная тема** — переключатель в сайдбаре (запоминается, перекрашивает и графики).
7. **Экспорт всего отчёта в Word** (`.docx`, настоящий OOXML) с корректным
   форматированием: заголовки, компактные таблицы, цвета, KPI, семантика, прогноз,
   **графики картинками** и выводы OpenAI. Плюс экспорт в JSON. Генерация `.docx`
   реализована в чистом Node (свой ZIP-архиватор), без внешних зависимостей.

## Ключевые метрики

| Метрика | Что показывает | Источник |
|---|---|---|
| **ИИ-цитирования** | Сколько запросов, где сайт указан источником в ответе Алисы | Keys.so (надёжно) |
| **Упущенная семантика** | Запросы, где конкуренты в ИИ-выдаче, а клиента нет | расчёт (разность множеств) |
| **Сильные стороны** | Запросы, где процитирован только клиент | расчёт |
| **Head-to-head** | Во сколько раз сильнейший конкурент цитируется чаще | расчёт |
| **Прогноз трафика** | Модель: кол-во упущенных запросов × визиты/мес на запрос | прозрачная, настраиваемая |

Прогноз считается по **количеству запросов** (надёжная величина), а не по сумме частотности
(её искажают несколько брендовых/навигационных запросов). Допущения (15 визитов/мес на
ИИ-цитирование, 50 — при ТОП-3 органики) заданы в `src/analysis.mjs` и легко меняются.

## Запуск

```bash
node --env-file=.env src/server.mjs
```

Затем открыть http://localhost:5173

Требуется **Node.js ≥ 22** (используется встроенный `node:sqlite` и нативный `fetch`).
Внешних зависимостей нет — `npm install` не нужен.

## Конфигурация (`.env`)

```
KEYS_SO_TOKEN=...     # токен Keys.so (заголовок X-Keyso-TOKEN)
OPENAI_API_KEY=...    # для выводов, нарратива и плана работ
OPENAI_MODEL=gpt-4o   # модель OpenAI
KEYSO_BASE=msk        # ИИ-выдача доступна только для базы msk
PORT=5173
```

## Архитектура

```
src/
  server.mjs    HTTP-сервер (zero-deps), REST API + SSE-прогресс + статика
  keyso.mjs     клиент Keys.so: троттлинг + ретраи на 429/5xx, поллинг «отчёт строится»
  analysis.mjs  сбор данных по домену + кросс-доменное сравнение, gap, прогноз
  openai.mjs    генерация выводов, сильных сторон, why-now, плана работ, питча
  docx.mjs      генерация .docx (OOXML): свой ZIP-архиватор + таблицы, стили, графики
  db.mjs        хранилище (node:sqlite): projects / snapshots / ai_queries
public/
  index.html, styles.css, app.js, chart.umd.min.js  (SPA + Chart.js локально)
data/
  analytics.db  «память» — сохранённые проекты
```

### Заметки по данным Keys.so
- ИИ-выдача доступна только для базы `msk`.
- Отчёты `organic/*` строятся асинхронно — клиент отдаёт `202`, сервис поллит до готовности.
- Keys.so ограничивает частоту запросов (429) — клиент троттлит (≥350 мс между запросами)
  и повторяет с нарастающей паузой, поэтому многодоменный анализ не срывается.
- Цитируемые в Алисе запросы — преимущественно **длинный хвост** (низкая частотность),
  поэтому ценность в первую очередь в **широте охвата** и **разрыве с конкурентами**,
  а не в сумме частотности.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/analyze` | запустить анализ `{name, domains:[{domain, role}]}` → `{jobId}` |
| `GET` | `/api/analyze/stream/:jobId` | SSE-поток прогресса + завершение |
| `GET` | `/api/projects` | список сохранённых проектов |
| `GET` | `/api/project/:id` | проект + расчёт сравнения |
| `POST` | `/api/project/:id/insights` | сгенерировать выводы OpenAI |
| `GET`/`POST` | `/api/project/:id/docx` | выгрузить отчёт в Word (.docx); POST принимает `{charts}` (PNG графиков) |
| `DELETE` | `/api/project/:id` | удалить проект из памяти |
| `GET` | `/api/config` | статус токенов и база |
